# 在 Idea 中借用 Craft 的表现能力

只在核心已确认、需要发散表现方式或判断概念可行性时读取。定位当前环境的 `video-craft` Skill，读取其 `references/capability-map.md`；资料库中对应 `03-design-delivery/video-craft`，运行时按已安装 Skill 路径定位。不复制能力表。Craft 不可用时继续构思，并标明未验证的实现前提。

52 方法解决创意操作，Craft 能力解决如何让观众经历它。先沿方法发想，再问：除了静态页面/口播插图，这个意思能否通过物件变化、数量迁移、空间展开、关系显现、声音与画面反差表达？只为有潜力的概念查相关能力，不逐张方法卡遍历所有工具。

把“表现机会”写进已有候选/production-brief：看到什么变化、为何服务核心、素材前提、可用能力与不确定性。尚未试过的实现标为提案；涉及核心可行性才做小试片，不在发想阶段精做全片。

讨论后的画面要区分：作者锁定的创意动作、开放给 Craft 的表达目标、仅供参考的样张。确认一种画法不等于所有布局都锁死；确认内容不等于同意 Agent 的样张排版。

画面表现能反过来改善口播：能看明白的关系少念一点，揭晓需要的停顿保留，对应的过渡提前准备。改变作者意思或已批准口播时带着具体段落讨论，不借“更好动画”擅自重写。
