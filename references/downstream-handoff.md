# 录制前做画面，录制后交剪辑

Video Idea System 在作者批准可录稿后结束，不因下游工具已安装就自动继续。

## 工作顺序（已定，不要倒过来）

**定故事与文案 → 做好静态画面 → 录人声 → 剪时间线 → 把画面挂到实测时间 → 轻动画跟着实测音频 → 合成。**

静态画面在**录制之前**就做好；`visual-plan.json` 也在录制之前就到做画面那一步。动画是**录后**才按实测音频加的。

## 纯口播

- 这一形状**不需要调做画面那一步**。
- 需要转写、选 Take、删停顿、剪切和导出字幕：交给 `video-craft`。
- 只需人工剪辑：交付 `script.md` 与素材备注。
- 纯口播的片照样过念稿审阅页（只省略 `--visual-plan`）；这里说的只是它不需要做画面。

## 口播 + 画面

### 第一步 · 录制之前，交给做画面那一步

把 `visual-plan.json` 交给**做画面那一步**——`planners-ppt-hell` 的视频路线，是另一个 Skill，不是 `video-craft` 的视觉层，也不是 `hyperframes` / `frontend-design` 一类动画工具。

```text
visual-plan.json        # 内容契约 + 上屏文字与花字声明 + 每屏样张
assets/                 # 契约 sample.assets[] 引用的那几张真实素材，一图一文件
```

`assets/` 是**上游 Stage 4B 拼样张时产出**的：把 `sample.assets[]` 用到的真实文件放成 `deliverable/assets/<文件名>`，目录内容恰好等于契约引用的那几张（做画面那一步会对 `--assets` 与契约引用做全等检查：少了它拿到缺口，多了它被拦下）。契约里指向别处的路径（例如 `data/users.csv`）留在原地，不复制进来。

它接手时，画面**已经差不多定调了**：

| 已经定调、它不得改（继承） | 它仍然自由决定 |
|---|---|
| 这一屏用哪张图（真实路径） | **风格**从 `video-craft` 的风格库（`video-craft/visual/themes/`）里挑哪一个、这个风格大方向怎么落。“模板库”不等于“风格库”——画面风格来自风格库 |
| 两张图（或多张）之间是什么关系：并列 / 对比 / 因果 / 时序 | 网格、栏数、沟槽、边距、纵向步长 |
| 用什么样的模型展示（列表 / 流程 / 交叠 / 矩阵 / 物件示意） | 层级角色与字号档位怎么取 |
| 模型上必须出现哪些标签、数字、术语（原样） | 色彩角色、强调色落在哪里 |
| 花字层的内容与出场顺序 | 跨页锚点、页码页脚的位置，整套节奏 |
| `screen_id` / `beat_id`（原样成为 `page_key`，不改名不重新编号） | 图形的具体几何、留白多少、构件选用 |
| — | 视频画面自己的技术约束：16:9 画幅、可被动画指名的图层、字幕安全区 |

**照声明的画，不判断声明。** 它的出口是**拿走 SVG**（页面源是 `_internal/02_svg_source/<page_key>.svg`），不做 PPTX 导出。画面上的文字与花字照契约声明画；`script_hash` 的核对责任见下面「版本闸门」一节。

### 第二步 · 录制之后，交给 `video-craft`

用户完成录音并得到句子级 SRT 后，连同做画面产出的静态 SVG 一起交给 `video-craft`：

```text
input/
├── audio.mp3
├── subtitles.srt
├── script.md
├── visual-plan.json      # 内容契约 + 上屏文字与花字声明 + 每屏样张
├── visual-blueprint.md
├── production-brief.md   # 七项，含片级形状与按 Beat 的作者决定
├── scenes/               # 做画面那一步产出的静态 SVG，一屏一个 page_key
└── assets/               # 契约引用的那几张真实素材（与上游 deliverable/assets/ 同一批）
```

下游规则：

- SRT 是唯一精确时间真相源；
- 每屏的 `beat_id` 只说明它对应哪一段口播，**不规定该段内部的动画状态**；着重动画在录后按实测音频加，不是上游的契约状态；
- 下游根据最终口播与 SRT 对齐 Beat；
- **样张的设计不可继承**（下游可以完全重做版面）；但**素材选择与那一层简单设计要继承**：这一屏用哪张图、图与图的关系、用什么模型展示、模型上必须出现哪些字、花字层的内容与出场顺序；
- **上屏文字与花字的声明在 `visual-plan.json`**：`must_show` 里以「文字：」开头的条目、`exact_labels`、`sample.captions[]`。下游只检查渲染出来真的会出字的地方与它是否一致，**不另立第二份声明**；
- **「文字：」是契约的标记，不是正文的字符**：下游把它写进页面时剥掉这个前缀，正文从它后面第一字开始；`sample.assets[].label` 是审阅页的图注，不是上屏文字，**不把它画上屏**；
- 下游保持一 Beat 一屏，不把多个上游屏合并成跨段总图；录制后画面只做轻动画与合成，静态画面不再重画；
- 下游不得丢失 `must_show`、`must_express`、`exact_labels` 和 `evidence`；如果必须表达的事实不能被当前模型清楚承载，应在下游反馈中暴露并回到内容契约处理，不用自行改写理论；
- 录制内容明显改变原意时，返回 Video Idea System 更新契约与样张。

### 版本闸门：`script.md` 就在契约旁边，拿到契约的那一侧就核

`visual-plan.json` 的 `script_hash` 是**最终 `script.md` 的 sha256**。`script.md` 与 `visual-plan.json` 同在 `deliverable/` 里，所以**两个下游都够得着它**——都核，各管自己那一段：

| 谁 | 它核什么 | 发现了会怎样 |
|---|---|---|
| 做画面那一步（`planners-ppt-hell` 的视频路线） | 顺着契约文件所在目录找到 `script.md`，算 sha256 与契约的 `script_hash` 比对；另外记下 `visual-plan.json` 自己的 sha256，契约文件被换过也说话 | 不符 → **error，拦下**。**这一遍是唯一还来得及的**：工序是「做好画面 → 录人声 → 剪」，作者是**对着画面录**的 |
| `video-craft`（第二步剪辑） | `input/` 里同时有 `script.md` 与 `visual-plan.json`，再核一遍 | 不符 → 停下来问作者：重绑 Hash，还是脚本改过、要回上游更新契约。**这一遍只能事后发现**——人已经录完了 |

真的找不到 `script.md` 时报「**无法核对**」，不报成功。

本 Skill 在 `stages/05` 交付前用 `validate-visual-plan.mjs --script` 绑一次；下游两处各核一次，各自管自己那一段。

## 禁止抢跑

- 不在可录稿阶段生成 SRT；
- 不手写时间码或动画状态；
- 不开始剪辑、渲染或动画；
- 不替用户决定录制后的 Take 与节奏；
- **做画面那一步开工之后，改片级形状不再免费**：`visual-plan.json` 在录制之前已经到了那一步，此后每改一屏就要重做对应的页面。
