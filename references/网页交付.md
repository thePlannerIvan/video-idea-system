# 网页交付

候选和段落脚本默认用两个离线网页呈现，同时保留可编辑内容。模板沿用作者提供的 `创意展示.html`、`脚本.html`（SkillLab web 版本）的纸色、字体、卡片布局、三张翻页和分段表格，已移除案例正文及项目图片。模板在 `assets/web/`，无需读取原项目或联网。

## 内容先成立，再渲染

项目 `_idea/current.md` 是当前核心与选择的依据。页面数据沿用同一 core 版本；页面里的“已确认”必须有真实对话依据。输出放到项目 `_idea/web/`，不要覆盖 Skill 模板。更新已交付版本前保留旧稿，避免把新提案当作旧批准稿。

生成 `ideas.json` 或 `script.json`，字段中的内容均为纯文本，换行用 JSON 的 `\n`，不填 HTML 标签。卡号与详细筛选过程留后台，前台优先让作者理解点子。

两种页面的共同字段：

```json
{
  "title": "本片题目",
  "core_version": "core-v1",
  "status": "候选待讨论 / 脚本粗稿",
  "audience": "说给谁",
  "insight": "已讨论的洞察，保留假设身份",
  "shift": "希望从什么理解走向什么理解",
  "takeaway": "想留下的那句话",
  "notes": "材料依据或影响当前选择的待定事项"
}
```

候选页再加 `core_confirmed: true`（只有实际确认才填），以及 `cards` 数组，通常 9–12 项。每项格式：

```json
{
  "id": "I07",
  "name": "简明名称",
  "role": "结构",
  "one": "一句话概念：做什么，让哪个意思成立",
  "mechanism": "为什么这些具体动作与核心有关，不能用卡名代替解释",
  "flow": [
    {"label": "开头", "text": "看见/听见什么"},
    {"label": "变化", "text": "发生什么变化"},
    {"label": "落点", "text": "留下什么"}
  ],
  "materials": "现有、计划拍、尚缺；最低成立条件",
  "risk": "实际风险与可用替代；没有发现硬伤就如实写明"
}
```

`role` 为“结构”或“零件”；零件的 `flow` 改写为放置位置及前后衔接。编号跨批稳定，不因翻页改号。可选 `pool` 是实际发散摘要的字符串数组，折叠在候选之后，不先给作者看整面原始点子墙。数量只报实际记录。页面按钮仅翻页，保留、淘汰、疑问回到对话记录，不声称已自动收集用户选择。

脚本页再加 `segments` 数组：

```json
{
  "name": "01 段落名 / 作用",
  "duration": "约 20 秒",
  "copy": "实际口播句子。\n另一句。",
  "visual": "具体画面和动作，注明计划拍/已有素材/示意",
  "text": "实际花字；不需要时填无"
}
```

`duration` 可省略，页面显示“未估算”；这是拍摄前粗稿，不接收实测时间轴。可选 `questions` 是待讨论、待补素材的字符串数组。文案还应保存为项目中的 Markdown，便于修改。

## 生成与查看

```bash
python3 <skill>/scripts/render-review.py ideas <project>/_idea/ideas.json --out-dir <project>/_idea/web
python3 <skill>/scripts/render-review.py script <project>/_idea/script.json --out-dir <project>/_idea/web
```

只生成当前阶段需要的页面。两页均已存在且使用同一核心版本时，分别设 `script_available: true`、`ideas_available: true` 再渲染以显示互链；未完成脚本时不放空链接。内容替换已做 HTML 转义，无外部资源依赖。

打开当前页面给作者看，核对第一批/最后一批各有预期卡片、稳定编号、手机窄屏可读，以及脚本的换行和三类内容没有串列。完成候选页不自动推进脚本；按概念锻造的讨论进程工作。
