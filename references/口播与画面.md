# 从概念到可录口播与逐段画面

核心和框架已定后使用。原 Story 的能力已并入本 Skill，这一段流程在本 Skill 内完成，不需要另装前置。

## 深化口播

读取[口播写作](spoken-writing.md)，结合材料和作者真实改口建立语气判断。把确定的结构组织成稳定的 Speech Beat，逐段写能念出口的正文、必要桥接、例子与结论。内容复杂时先拿一个代表段讨论语气与密度，再在已授权范围完成全文；不机械增加审批。

保存 `deliverable/script.md`，格式为 `## beat-01｜段落名`。编号稳定，删掉某段无需重排其他编号。正文只放实际口播；舞台指令、画面、花字和素材路径放契约或制作说明，不混进要念的句子。作者要求保留已说出的原文时，保留原文；事实疑点单列给作者，不自行改写立场。

**这一步两种形状都要做。** 片级形状（纯口播 / 口播 + 画面）在这一步之前或之后都可能才定下来，它不影响先写出可录的口播。

## 逐段内容与画面

读取[视觉解释](visual-explanation.md)和[契约格式](visual-plan-contract.md)。这一节是**屏级**判断，不是片级路由：

- **这一屏要不要画面**，由这一段口播自己决定——画面承载证据、关系或创意动作时给它一屏；一段口播拿掉画面仍然完整成立，就不给。
- 有画面的屏：一 Beat 一屏，输出 contract 5.0 的 `deliverable/visual-plan.json` 与同内容的人读版 `visual-blueprint.md`。
- 每屏说明 question、must_show、must_express、exact_labels、evidence；`sample.captions` 记录花字。这里只规定画面需要传达什么。
- **一屏不得声明多个状态**；一段口播要观众先看 A 再理解 B，就拆成两个 Beat。状态属于下游的时间分组，**着重动画是录后按实测音频加的，不是契约状态**。
- **`must_show` 可以是空数组**：没有任何上屏文字的屏合法（可以就是一张图）。但每一屏都要在审阅页上显示出点什么，所以这时必须用 `sample.assets[]` 声明它的真实素材。

**这一屏的简单设计在念稿审阅页上定下来**：放哪张图、两张图是不是对比关系、用什么样的模型展示、模型上有什么字。刻意粗糙可以，**没定不行**——它随 `sample` 落盘并被下游继承（版面不继承）。

**样张只用真素材**，标注过的概念示意不算样张。素材缺口在这一步就暴露，用手上真有的素材写，**不要带到做画面那一步**。缺素材如实显示缺口。作者明确指定的画面形式另存为决定，不要因为样张可重做而丢掉作者要求；存法见[交给 Craft](交给Craft.md)。Agent 的画法建议与作者决定分开。

## 片级形状：只有两个值

屏级判断汇总起来就是片级形状，**只有两个值**：**纯口播** 或 **口播 + 画面**。

- 它**只决定一件事**：要不要调做画面那一步。
- 它**不决定**要不要过念稿审阅面——两种形状都要过。
- 内容类型（清讲 / 强知识 / 混合）**不是路由维度**，不要用它来分叉流程。
- 纯口播的片**仍然可以有一屏带画面**，因为带不带画面是屏级判断；不要为这种情形发明第三种形状。
- 记在两处：`_idea/current.md`（当前决定的唯一入口）与 `deliverable/production-brief.md` 的「当前交付目标」。谁改、什么时候改不再免费，见[交给 Craft](交给Craft.md)。

## 同屏念稿审阅（唯一的确认面）

**整部片只有一个确认面，两种形状都过。** 一 Beat 一屏，左口播、右样张、下方分别记录口播与视觉反馈：

```bash
node <skill>/scripts/start-read-aloud-review.mjs --script <project>/deliverable/script.md --visual-plan <project>/deliverable/visual-plan.json --review-dir <project>/_idea/reviews/script --asset-root <实际素材根> --port 0
```

纯口播省略 `--visual-plan`（**省略的是右半，不是这一页**）。脚本自动打开页面，等待作者返回；不轮询、不替作者填写反馈。审阅页在这一页上就把画面定调到「故意简单但已经定了」的程度；粗样张不代替动态与声音审阅。反馈绑定稿件、契约和素材指纹，更新后旧反馈只作历史依据，不能冒充新版整体批准。

作者念稿、贴回原文或明确免去朗读后，先以最新口播反馈重建需要变化的 Beat，再重配画面；不是只改视觉而保留被作者否定的旧文案。逐条记录“反馈 → 对应正文/画面改变”，作者明确作废的旧稿与旧反馈退出当前依据。形式反馈写入制作决定，交 Craft 实现；需要重新讨论核心时更新 `_idea/current.md` 的版本及替代关系，而不是让新旧决定同时有效。末尾用批评清单检查事实、结构、语气和机制。

```bash
node <skill>/scripts/validate-visual-plan.mjs <project>/deliverable/visual-plan.json --script <project>/deliverable/script.md
```

该校验只证明格式和稿件对应，不证明缺口素材存在、作者批准或创意已实现。最后交付口播、契约、素材与制作说明；标明“待审/已确认”及具体依据。没有录音不阻止内容包交给 Craft 进行制作规划。

## 交接前的三项澄清

- 用真素材样张确认“看什么”；关键动画用起始、变化、结束状态或简短动作说明确认“发生什么”，不在这里展开最终动画制作。
- 作者指定“这句话才出现”时，保留触发原句及顺序，实际秒数由 Craft 根据录制决定。画面变化不能只绑定一个宽泛 Beat。
- 提词正文不含切画面指令；交接携带最新口播、当前样张、作者动作和触发语，以及已确认/待定状态。**静态画面在录制之前就做好**（见[下游交接](downstream-handoff.md)），交接顺序不是「先录完再想画面」。
