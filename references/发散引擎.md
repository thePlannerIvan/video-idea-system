# 发散引擎

用于找创意和反馈后的再发散。目标是产生不同且能表达作者意图的点子，不是完成一套抽卡仪式。先生成再评价；候选成形后才加载候选诊断。

## 1. 以确认的核心为发散边界

读取 `_idea/current.md` 中确认过的受众、洞察、期望变化和留下的话，注明本轮 core 版本。尚未确认时返回[洞察与目标](洞察与目标.md)。允许许多不同表现机制，但候选不能暗中各讲一个传播目标。

## 2. 方法读取：相关、探索、挑战

脚本路径以当前 Skill 目录为基准，项目路径用绝对路径；下面的路径是调用示例，运行时替换。卡库内置于 [cards.json](cards.json)，来源与整理边界见[来源说明](来源说明.md)。不用读取整个 JSON，更不用全量案例库。

### 先读完整导航，再按卡读原理

```bash
python3 <skill>/scripts/draw-cards.py index
```

一次列出全部 52 张的名称、导航问题和交叉标签；同会话无需重复加载。导航问题是本 Skill 的改编提示，卡片原理才是进一步理解的依据。

每轮包括三路，默认是可调整的工作量，不是创意评分标准：

1. **相关路**：Agent 从导航选约 2 张与本轮问题有实际联系的卡，说明它能改变什么。允许延用有效方法；不要只凭“主题相似”套旧答案。
2. **探索路**：脚本另给约 4 张在记录范围内尝试较少的卡。此路不按主题相关性排序，也不被相关路替代。首次使用全员并列；同等尝试次数才用标签覆盖和 seed 打破平手。不会总从小编号起步。
3. **挑战路**：完成第一批点子后，再读导航中约 2 张本轮尚未尝试的卡，针对实际同质性选择。先写“已有点子都在做什么”，再写“新途径改变什么”。类别不同不等于机制不同，距离主题远也不是有效挑战的充分条件。

```bash
python3 <skill>/scripts/draw-cards.py plan --anchor 11,16 --explore 4 --seed 20260919 --history <project>/_idea/method-history.json
python3 <skill>/scripts/draw-cards.py show 11,16,其他实际返回卡号
```

`plan` 只输出导航，不算读过原理；必须用 `show` 读取每张真正发想的卡。没有找到相关卡也可不传 `--anchor`，从探索开始。探索卡看似难用时先尝试转换一次，不因陌生就重抽到熟悉卡；确实触犯作者边界或没有形成点子，记下实际尝试和原因，不编造数量。

挑战依据看产物，例如：全在“证明谁错了”时试着观察或共情；全是二元对比时试着让事物在时间中变化；全靠象征时尝试一次可观察的行为。卡号不预设固定对立配对。若缺的是素材或作者意图，应回到材料/讨论，不能靠继续抽卡掩盖。

### 轮换记录如何防止长期只读几张

用户指定的记录路径优先。正常创作位于已识别的视频集合中时，默认在集合目录共用 `_idea/method-history.json`（本工作区为 `05-VideoProject/_idea/method-history.json`），让新视频也避开长期重复；首次采用时说明路径。没有集合目录则使用当前项目 `_idea/method-history.json`。单次临时试验与隔离测试始终留在各自输出目录，不污染生产记录，不写 Skill 安装目录或隐蔽的全局文件。下列命令中的 history 路径统一替换为这次选定的同一文件。

每轮发散落盘后记录**实际按原理尝试过的卡**，包括没有找到满意点子的尝试；仅列出、读过或出现在组合引用中的卡不充数。`--run` 在共享集合中使用“项目名/轮次”作为唯一键，同轮更新是替换而非重复计数。不同写入者同时运行会被锁保护，遇锁稍后重试；生成期间不预占卡，重叠运行可能探索到相同方法。

```bash
python3 <skill>/scripts/draw-cards.py record --history <project>/_idea/method-history.json --run 题目名/r1 --cards 实际尝试卡号 --artifact <project>/_idea/发散-r1.md
python3 <skill>/scripts/draw-cards.py stats --history <project>/_idea/method-history.json
```

只有作者已选定时，才以同一 `--run`、完整原参数加 `--selected 构成选定概念的卡号` 更新记录。无关方法不为了统计强行加入。

脚本保证探索名额优先给尚未尝试/尝试更少的卡，遍历后继续均衡轮换；显式相关卡不受这个限制。**保证的是尝试机会，不是被选中的结果均匀。** `stats` 分开显示尝试覆盖与选定次数：选定集中但探索充分，可能是作者偏好；尝试本身集中才先修检索。没有共享历史时，不能声称检查过跨视频的长期集中度。

## 3. 大量发散，延后评价

读过原理后，尝试将其中的操作移到当前素材：谁做什么、对象怎样变化、观众如何感受到意图。每卡先尝试约 5–10 个具体点子，一轮通常数十个；有真实增量可以扩展至上百个，不以达到一百为任务。不要只换名称、换比喻表皮。相关与探索先并行思考，完成后做挑战路。

把初步点子编号并留档，此阶段不按拍摄成本或“观众不会喜欢”先筛掉。作者明确的边界始终有效。数量不足就写实际数和困难，“同上、未成立”不计为点子。

在初步点子中出现值得展开的表现时，按[表现能力咨询](表现能力咨询.md)查 Craft 导航，尝试一种不同于静态页面/口播插图的可行机制；作者明确只要清讲时不强加。能力咨询不替代探索路，也不要求使用更多工具。

## 4. 筛选与组合

评价每个点子时看：

- 它服务作者的意图还是暗中改了题？不同表现角度可以并存，传播目标沿用已确认版本。
- 具体动作与要表达的意思怎样相连？如果拿掉创意名称和解释，观众实际获得什么？不能凭模型一句“观众自然会懂”判通过。
- 事实与推断站得住吗？演绎只能说明设定中的关系；真实实验也可能不支持预设主张。
- 在真实资源下能执行吗？先考虑合适替代，再说明损失；不能退成纯口播不构成自动淘汰理由。
- 是独立想法，还是另一个点子的重复？“业内才懂”不是无效的充分理由，取决于本片受众。

保留淘汰理由，区分“偏离意图、关系说不通、证据不足、当前资源不够、重复”和审美偏好。没有依据的“已是烂套路”“观众不关心”只能算待讨论风险。

读[批评清单](批评清单.md)的“候选阶段”做一轮自筛，修掉可修的问题；候选池只留下机制说得通且风险有交代的方案。语言润色留到成稿后。

好点子可提出组合建议，保留原编号供作者选择，不在后台替作者锁定融合版：一个建立关系，一个让关系可感；一个推进过程，一个留下记忆。写明组合比单独使用多出了什么。增益不成立就保持单机制，不强迫至少五组或每条多卡。

## 5. 检查实际差异，再交给作者

对存活点子按“表达角度、观众经历的变化、证据/情感机制、承载形式”对比。同一投影仪可以承载不同想法，不同道具也可能只是同一招。若只有形式换皮，用挑战路再试；若继续扩散已无增量，带着明确困难回到作者讨论。

后台保存编号点子、方法依据、简短筛选结论，以及实际生成/淘汰/保留数量；不交付推理流水。前台默认准备 9 或 12 个候选，包含完整结构和有价值的段落零件，明确标识用途。每批展示 3 个，同批便于比较、跨批保持差异；不是总共只给 3 个。不足 9 个时先针对缺口补充发散；仍无增量就展示实际数量和困难，不以换皮凑数。进入[概念锻造](概念锻造.md)和[网页交付](网页交付.md)。一轮结束只说明读/试过哪些方法及候选差异，不能凭四类覆盖宣布“充分发散”。
