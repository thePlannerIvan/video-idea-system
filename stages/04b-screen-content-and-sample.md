# Stage 4B：有画面的屏——内容契约与粗糙样张

## 这一步在做什么

口播写完后，**给需要画面的那些屏**建立内容责任：告诉下游这一屏画面上必须呈现哪些信息，并配一张**只用真素材拼的粗糙静态样张**。整条流程的第 8 步。这里建立的是内容责任与那一层简单设计，不是画面方案：不画最终画面、不声明状态、不决定时间段、不做设计。

**这是屏级步骤，不是形状分支**：只为实际要画面的屏做。纯口播的片通常一屏都不做；但它也可以有一屏带画面，那就只为那一屏做。

## 为什么需要这一步

下游做画面的人拿到的不该是一句“配点素材”，而是一份能被照着画、也能被检查的清单：这一屏要回答什么问题、画面上必须出现什么、哪些字必须原样、素材是哪一张。没有它，做画面只能自己发明内容，字闸门也没有比对对象。样张的作用是让作者在念稿时**看见**这一屏，而不是读一串条目文字。

## 输入及其作用

- `deliverable/script.md`：哪些 Beat 存在、它们各自在讲什么；`visual-support` 注释指出作者已经想到的素材。
- `.video-story/story-lock.md`：必留的事实、案例与视觉对象，不能在建屏时丢。
- Storyline 的屏级判断：哪些 Beat 要给画面——只为这些建屏。
- 磁盘上的真实素材：样张只能从已有素材里挑；找不到就如实写缺口。
- `../references/spoken-writing.md`、`../references/visual-explanation.md`、`../references/visual-plan-contract.md`：口径、字段与可用素材类型。

## 主要结果与认知动作

一份 `deliverable/visual-plan.json`（内容契约 5.0）、一份人读版 `visual-blueprint.md`，以及 `deliverable/assets/`。认知动作是**把口播翻译成画面责任**：这一段要回答什么问题 → 画面上必须出现哪些对象、事实、数字、标签 → 哪些字必须原样出现 → 用哪张真实素材、它们之间是什么关系。

内容契约只回答：

- 这段口播要回答什么问题；
- 画面上必须出现哪些对象、事实、数字、标签或证据；
- 画面必须表达哪些语义事实或差异；
- 哪些文字、数字、术语必须原样出现（**这就是上屏文字与花字的声明**，下游只读不另立）；
- 真实数据或资料从哪里来。

## 判断框架

- **一屏一认知单元**：一屏恰好绑定一个 Speech Beat，一个 Beat 最多一屏，一屏只有一种状态。
- **只写内容**：读者能从契约里知道“必须出现什么”，但读不出“怎么构图”。出现布局、动画、状态、秒数就是抢跑。
- **可被外人执行**：把契约交给没有参与讨论的人，他也能说出这一屏必须有哪几样东西。
- **样张是真的**：每一格都能在磁盘上打开；摆得难看没关系，摆的是别的东西不行。
- **简单设计已定**：放哪张图、两张图是不是对比关系、用什么样的模型展示、模型上有什么字——四件事有结论，不是留白。
- **常见误判**：把“想表达的意思”写成“画面的画法”；用示意图补素材缺口；把口播摘要当样张；为纯口播的 Beat 也建屏。

## 不要做什么

- 不回答画面具体怎么构图；
- 不用流程图、三维模型、圆圈、矩阵等表现形式来定义这一屏；
- 不写“左边/右边/中间”放什么作为**表达设计**；
- 不写如何解决问题或引导观众；
- 不写节点从哪里飞进来；
- 不写什么时候切屏、保持几秒；
- 不把动画拆成几个 State（**一屏多状态在这里被禁止**）；
- 不指定配色、字体、动效风格。

## 工作方式

1. 完整读取 `../references/spoken-writing.md`、`../references/visual-explanation.md` 与 `../references/visual-plan-contract.md`。
2. 按 Storyline 写代表性口播 Beat，确认说话方式、信息密度和主张。
3. 对**要画面承担这一段**的 Beat，创建且只创建一屏，填写问题、必见对象、必须表达的事实、固定文字和证据来源。
   **没有任何上屏文字的屏是合法的**（可以就是一张图）：`must_show` 留空数组，但必须用 `sample.assets[]` 声明这一屏摆哪张真实素材——审阅页总得显示出点什么。
4. 检查每屏只绑定一个 Beat，**且一屏不声明多个状态**。若一段口播需要两屏，或同一屏需要跨两段才能说完，先重切 Speech Beat，让一段口播与一屏成为完整认知单元。着重动画是**录后**按实测音频加的，不是契约状态。
5. 为这一屏拼样张：**从磁盘上已有的真实素材里挑**，按 `sample` 字段写清摆法与花字层。样张只用真素材、静态摆放、不做动效、不排字体配色。**标注过的概念示意不算样张**；找不到可用素材时如实写成缺素材，不要用示意图假装。
6. 在样张上把**这一屏的简单设计**定下来（放哪张图、两张图是不是对比关系、用什么样的模型展示、模型上有什么字）：摆法落在 `sample` 的字段上，模型用一句话写在 `sample.note`，模型上要原样出现的字写进 `exact_labels` 或 `sample.captions`。**粗糙可以，没定不行。**
7. **产出 `deliverable/assets/`**：把 `sample.assets[]` 用到的真实文件放成 `deliverable/assets/<文件名>`，目录里恰好是契约引用的那几张——少一张下游拿到的是缺口，多一张做画面那一步的全等检查会拦下来。契约里指向别处的路径（例如 `data/users.csv`）留在原地，不复制。
8. 检查口播没有朗读画面中的全部标签，样张也不是口播摘要。
9. 完成 `script.md` 和 `visual-plan.json`，再整理人读版 `visual-blueprint.md`。
10. 进入统一审阅页；**一 Beat 一屏**，每屏左边念口播、右边看样张。这一页是整部片唯一的确认面，两种形状都要过。

### 口播稿

按 Stage 4 的 Beat 格式写入 `deliverable/script.md`。口播负责方向、判断、解释和结论，不朗读所有数字、节点和标签。

### 粗糙样张（`sample`）

样张回答的是**“这一屏大概是什么样”**，让用户在念稿时就能看到画面，而不是读一串条目文字。

- 只用真素材：磁盘上已有的页面截图、联系表、原始数据行、报告实物、录屏、归档图片；
- 只做静态摆放：一屏一张 16:9 画面，素材按 `layout` 摆进去，花字层压在下沿；
- 不做动效、不做转场、不调字体配色、不追求精致；
- 素材不够就露出缺口，不要补画示意图；
- 样张不是设计交付：下游有权忽略它的摆法，但**素材选择与这一层简单设计要被继承**，缺口也**不得忽略**。

字段与可用素材类型见 `visual-plan-contract.md`。`visual-blueprint.md` 按同一内容写成人读版，例如：

```markdown
## screen-beat-03｜beat-03｜平台反馈机制

- 问题：创作者加入后，平台的反馈机制发生了什么变化？
- 必须出现：用户、平台、创作者三个角色；激励变化前后的关键数字。
- 必须表达：创作者加入后新增的作用方向。
- 固定文字：三方关系的完整名称。
- 证据：SRC-01#p2。
- 样张：hero；左边机制前后对照页整页，右边三张逐块明细截图；模型：三方关系示意；花字「加入前 / 加入后 / 新增的作用方向」。
```

## 人机介入

不单独找作者确认。屏的内容责任与简单设计直接进入 Stage 5 的念稿审阅面，作者在那里一边念一边看，不满意就写在视觉反馈框里。只有素材缺口大到要改主张或结构时，才回到 Stage 2 / Stage 3。

## 产物

- `deliverable/visual-plan.json`：内容契约 5.0，每屏一 Beat。
- `deliverable/visual-blueprint.md`：同一契约的人读版。
- `deliverable/assets/`：恰好是契约 `sample.assets[]` 引用的那几张真实素材。
- 素材缺口清单（写进契约与 `production-brief.md`，不留在对话里）。

## 完成标准

- **语义完成**：`script.md` 可以直接朗读；内容契约只规定“呈现什么”，没有抢做画面设计与动画时序；每屏恰好绑定一个 Speech Beat，每个 Beat 最多一屏，一屏只有一种状态；没有上屏文字的屏用 `sample.assets[]` 声明了素材，审阅页能显示出东西；每项非显然信息都有来源；每个有画面的 Beat 都有样张，样张里的素材真实存在、路径可解析，且这一屏的简单设计已经定下来；没有画面的 Beat 没有被强制添加画面要求或样张；两份内容可以进入同一个审阅页。
- **机器检查**：
  ```bash
  node "<本 Skill 目录>/scripts/validate-visual-plan.mjs" \
    "<project>/deliverable/visual-plan.json" --script "<project>/deliverable/script.md"
  ```
  退出码 0；再用 `node "<本 Skill 目录>/scripts/check-handoff-artifacts.mjs" --project "<project>"` 确认 `deliverable/assets/` 与契约引用全等。有样张的 Beat 与 `script.md` 里带 `visual-support` 注释的 Beat 对不上时，逐条说明是跳过还是漏了。
- **不能由 Validator 证明**：这一屏的素材选得对不对；简单设计是不是表达了该表达的事；样张有没有把作者引到错误的画面上。
